# ADR-0001：使用 Electron 作为桌面运行时

- 状态：Proposed
- 日期：2026-08-05

## 背景

产品需要同时具备：

- macOS 与 Windows 桌面窗口控制。
- 透明、置顶、托盘和全局快捷键。
- 访问任意网页并保持较高 Chromium 兼容性。
- 多标签、站点登录状态和下载管理。
- 本地电子书阅读。

## 决策

第一阶段采用 Electron、TypeScript 和 React。网页标签使用 WebContentsView 管理，应用界面与网页内容使用不同的渲染边界。

## 原因

- Chromium 对现代网站兼容性较高。
- Electron 提供成熟的窗口、托盘、快捷键、session 和自动更新能力。
- macOS arm64、macOS x64 与 Windows 构建链成熟。
- TypeScript 可在主进程、preload、renderer 和共享类型之间保持一致。
- 团队可以优先验证产品体验，而不是先维护多个原生客户端。

## 未选择方案

### Tauri

安装包更小、系统资源占用潜力更好，但 macOS WKWebView 与 Windows WebView2 的行为差异会增加任意网页兼容和调试成本。后续若产品稳定，可重新评估。

### SwiftUI + WinUI

能获得更原生的系统体验，但需要维护两套 UI 和大量平台代码，不适合第一阶段快速验证。

### 纯网页/PWA

无法可靠提供置顶、透明窗口、全局老板键、托盘和本地系统集成。

## 代价

- 安装包和内存占用高于原生 WebView 方案。
- 必须持续跟进 Electron 和 Chromium 安全更新。
- 不可信网页与桌面能力隔离需要严格设计和测试。
- 部分系统行为仍需按平台适配。

## 复审条件

出现以下情况时重新评估：

- 安装包或内存成为阻碍采用的主要原因。
- 核心网站在 Electron 中存在无法解决的兼容问题。
- 产品决定只支持 macOS。
- 团队具备维护双原生客户端的长期资源。
