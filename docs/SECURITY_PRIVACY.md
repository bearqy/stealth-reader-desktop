# 安全与隐私设计

## 1. 安全目标

本产品同时处理任意网页、本地文档和桌面系统能力。首要目标是阻止网页或恶意文件越过隔离边界访问本机数据。

## 2. 威胁模型

主要威胁包括：

- 恶意网页尝试调用 Node.js、IPC 或文件系统。
- 恶意 EPUB、PDF、MOBI 文件利用解析器漏洞。
- 导航到 `file://`、自定义协议或危险下载地址。
- IPC 参数伪造、路径穿越和任意文件访问。
- 日志、崩溃报告或设置导出泄漏敏感信息。
- 透明或隐藏状态使用户误以为应用已经退出。
- 自动更新包被篡改。

## 3. 强制安全基线

### 3.1 Electron

- 启用 context isolation 和 sandbox。
- 禁止 renderer 与网页标签的 Node integration。
- 不在网页标签中加载应用 preload。
- 不允许远程内容进入具有桌面权限的 renderer。
- 不使用已弃用的 `remote` 模块。
- 所有 IPC 端点采用白名单和运行时校验。

### 3.2 导航与协议

- 允许 `https:`，对 `http:` 给出非安全提示。
- 默认拒绝 `file:`、`javascript:`、`data:` 等危险导航。
- 外部协议必须展示目标并由用户确认。
- 弹窗默认在新标签打开或由系统浏览器处理。
- 对下载文件名和保存路径进行规范化。

### 3.3 权限

摄像头、麦克风、通知、剪贴板、地理位置和 MIDI 默认拒绝。后续若开放：

1. 必须显示站点来源。
2. 必须由用户对当前站点明确授权。
3. 必须可以在设置中撤销。

### 3.4 本地文档

- 在隔离 worker/utility process 中解析。
- 解压 EPUB 时限制文件数量、单文件大小和总解压体积。
- 防止 Zip Slip 路径穿越。
- 不执行电子书中的脚本。
- 对 PDF JavaScript、附件和外部链接采用拒绝或明确确认策略。
- 全文索引只保存必要文本，不复制原文件到云端。

## 4. 隐私原则

- 第一阶段不需要账号。
- 书籍文件和阅读内容不上传。
- 历史、收藏和阅读进度仅保存在本机。
- 不出售、不共享用户浏览或阅读数据。
- 不采集输入内容、网页正文或书籍正文。
- 提供“一键清除本地数据”并说明不可恢复范围。

## 5. Cookie 与登录状态

- 由 Chromium session 管理网站 Cookie。
- 不读取或导出网站密码。
- 应用自身不记录登录表单内容。
- 清除站点数据时允许按站点或全部清除。
- 未来若支持多配置文件，使用独立 session partition 隔离。

## 6. 老板键与隐蔽功能

隐蔽功能不能被宣传为绝对不可发现：

- 隐藏不等于退出，托盘需提供明确运行状态。
- 防截屏是平台相关的尽力而为能力，不能承诺覆盖相机、外部采集卡或所有系统截图路径。
- 必须提供无法冲突的恢复路径或托盘“显示窗口”入口。
- 更新、崩溃和权限提示不能意外暴露历史敏感页面。

## 7. 更新安全

- 当前版本使用固定公开仓库 `bearqy/stealth-reader-desktop` 的 GitHub REST API 获取最新正式 Release，不携带用户凭证或阅读数据。所有更新 IPC 仅接受应用主 frame；安装地址、版本和本地缓存路径不能由 renderer 指定。
- 初始下载只允许该仓库的 HTTPS Release 附件路径，逐次检查重定向，仅允许 GitHub 附件 CDN。安装包按平台、架构、版本及安装/portable 类型严格匹配。
- 附件必须有 GitHub 提供的 SHA-256 digest；下载时核对流式摘要和字节数，下载不完整、超限或摘要不符时清理本次临时目录并拒绝交接。打开前再次校验，拒绝被修改的缓存文件。
- 当前为用户确认后的系统安装包交接：Windows 启动 NSIS，macOS 打开 DMG 供用户拖拽覆盖，portable 打开文件位置供手动替换。不会静默替换程序；操作系统仍可执行代码签名/Gatekeeper/SmartScreen 检查，不关闭或绕过系统验证。
- GitHub digest 校验确认下载内容与 Release 附件一致，不等于独立发布者签名。未来启用静默自动替换时，必须引入发布者签名、验签失败拒绝安装及回滚策略；当前未签名 macOS 不使用 Squirrel 自动替换。
- 禁止在客户端写入 GitHub Token、发布密钥、签名私钥或本机 GitHub CLI 凭证。

## 8. 日志与反馈

日志中禁止出现：

- 完整 Cookie、Token、密码和授权头。
- 完整带查询参数的敏感 URL。
- 本地文件正文。
- 用户剪贴板内容。
- 用户输入的搜索或表单内容。

用户主动提交问题反馈时，必须在发送前展示将要上传的信息。

## 9. 发布前安全检查

- Electron 安全配置自动化测试。
- IPC 能力清单评审。
- 任意导航和协议处理测试。
- 恶意压缩包、超大文件和路径穿越测试。
- 依赖漏洞扫描与许可证检查。
- 自动更新签名验证。
- 数据清除与卸载行为验证。
